# SQL Injection — Labs de PortSwigger

Tabla resumen de los 18 labs de SQL injection, en el **mismo orden** que aparecen en la [Web Security Academy](https://portswigger.net/web-security/all-labs#sql-injection).

La idea de esta tabla es tener un **pantallazo de en qué hacer foco**: dónde está la inyección (login, filtro, cookie…), qué la diferencia del resto, y lo indispensable que hay que probar para resolverla.

> En **todos** los labs el trabajo de fondo es el mismo: interceptar la petición, romper la consulta SQL con `'` y comentar (`--`, `#`) o rebalancear el resto. Lo que cambia entre labs es **dónde** entra la inyección y **cómo** se lee la respuesta (visible, error, boolean, tiempo, OOB).

## Cómo leer esta tabla / atajos mentales

- **Apprentice (1–2):** inyección clásica y visible. Romper con `'`, comentar con `--`. Casos de WHERE (retrieval) y login bypass.
- **UNION (3–10):** requieren **recon primero** → nº de columnas (#7) y columna de texto (#8) *antes* de exfiltrar. Diferencias por motor: Oracle necesita `FROM dual`, MySQL comenta con `#`.
- **Blind (11–17):** no ves los datos directamente. La clave es identificar **qué oráculo tenés**:
  - Respuesta cambia → **boolean** (#11)
  - Error condicional → **error-based** (#12, #13)
  - Nada visible → **tiempo** (#14, #15)
  - Ni tiempo → **out-of-band / Collaborator** (#16, #17)
- **Filter bypass (18):** el SQL es simple; lo que se practica es **evadir el WAF** con encoding.

### Lo indispensable a probar en cualquiera
1. `'` para ver si algo se rompe (error o cambio de comportamiento).
2. Comentar el resto: `--`, `-- ` (con espacio), `#`.
3. Condición siempre verdadera / falsa (`OR 1=1`, `AND 1=2`) para confirmar y calibrar.
4. Identificar el **motor** (Oracle / MySQL / MSSQL / PostgreSQL) — define sintaxis de comentario, concatenación, sleep y metadatos.
5. Si no hay salida visible → escalar a boolean → error → tiempo → OOB (en ese orden de "señal" disponible).
